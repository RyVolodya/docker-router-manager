# Docker Router Manager v0.7.0

## Routing

- Real host routing table from `ip -j route`.
- Host interfaces/addresses from iproute2.
- IPv4 forwarding ON/OFF.
- Add/delete DRM managed static routes.
- Managed routes are stored in `/data/routes.json` and re-applied when backend starts.

## WireGuard

- Native host WireGuard interfaces, not a nested WireGuard container.
- Create/delete interfaces.
- Automatic server key generation.
- Add/delete peers.
- Separate server-side AllowedIPs and client-side route AllowedIPs.
- Client route preset for current Docker networks.
- Full tunnel preset `0.0.0.0/0`.
- Generate client `.conf` text.
- PersistentKeepalive support.
- DRM restores configured WireGuard interfaces on backend startup.

Backend image now contains `iproute2` and `wireguard-tools` and keeps `network_mode: host` + `NET_ADMIN`.

## Upgrade

```bash
docker compose down
docker compose build --no-cache
docker compose up -d
```

Verify:

```bash
curl http://localhost:8081/api/routing/status
curl http://localhost:8081/api/wireguard/status
ip route
wg show
```

## Important

WireGuard private keys generated by DRM are stored in the protected `drm-data` volume so that interfaces and generated client configs can be restored/exported. Protect access to the DRM backend and its Docker volume.


## Build fix
WireGuard command runner now uses Node `spawn()` so `wg pubkey` can receive the private key through stdin correctly.


## v0.8.1 build fix

Express 5 route params are normalized with `paramString()` before being passed
to service functions. This covers Management, Firewall, Routing, and WireGuard.
